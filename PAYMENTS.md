# Онлайн-оплата (ЮKassa)

Через ЮKassa клиент **оформляет рассрочку на полную стоимость участка**.

Используется способ оплаты **`sber_loan`** — кредит/рассрочка от СберБанка.
Банк перечисляет продавцу всю сумму сразу, дальше клиент рассчитывается с банком.
Обычных платежей картой, брони и оплаты по частям на сайте нет.

### Ограничения, о которых надо помнить

| Что | Значение |
|---|---|
| Сумма одной заявки | от 3 000 до **1 500 000 ₽** |
| Кто может оформить | гражданин РФ с действующей дебетовой картой СберБанка и доступом в СберБанк Онлайн |
| Срок решения банка | до 8 ч (до 50 тыс), до 28 ч (50–200 тыс), до 72 ч (свыше 200 тыс) |

**Участок дороже 1,5 млн через сайт оформить нельзя.** И сервер, и форма проверяют
лимит: кнопка блокируется, клиенту показывается телефон менеджера.

Альтернативный способ «Плати частями» (`sber_bnpl`) ограничен 50 000 ₽ — для участков
не подходит. Способ задаётся переменной `YOOKASSA_PAYMENT_METHOD`; если оставить её
пустой, ЮKassa покажет все методы, включённые в личном кабинете магазина.

Страницы: `/#/pay` — форма оплаты, `/#/pay/result` — экран результата.
Ссылка «Оформить рассрочку» стоит в шапке, футере и в обоих калькуляторах.

## Как это устроено

```
Браузер                    Хостинг reg.ru (PHP)              ЮKassa
   │                              │                             │
   ├─ POST /api/pay.php ─────────►│                             │
   │   имя, телефон, e-mail,      ├─ берёт цену из каталога ───►│  создать платёж
   │   выбранный участок          │                             │  (sber_loan)
   │◄──── ссылка на оплату ───────┤◄─── confirmation_url ───────┤
   │                              │                             │
   ├──────── редирект на страницу оплаты ───────────────────────►│
   │                                                             │
   │◄─────── возврат на /#/pay/result ───────────────────────────┤
   │                              │                             │
   ├─ GET /api/status.php ───────►├─ спрашивает статус ─────────►│
   │                              │                             │
   │                              │◄── POST /api/webhook.php ────┤  оплата прошла
   │                              ├─ Telegram + Google Sheets    │
```

**Сумму считает сервер, а не браузер.** Клиент передаёт только тип платежа и
стоимость участка (она проверяется по границам из конфига) — подменить сумму
через DevTools нельзя.

### Файлы

| Файл | Назначение |
|---|---|
| `public/api/pay.php` | Создаёт платёж, возвращает ссылку на оплату |
| `public/api/status.php` | Статус платежа для экрана результата |
| `public/api/webhook.php` | Уведомления от ЮKassa → Telegram + Google Sheets |
| `public/api/ping.php` | Диагностика (можно удалить после проверки) |

| `public/api/lots.json` | Запасной каталог, если таблица не настроена или недоступна |
| `public/api/config.example.php` | Шаблон конфига со всеми настройками |
| `.github/scripts/make-config.py` | Собирает боевой `config.php` из секретов при деплое |
| `src/services/payments.ts` | Вызовы API из фронтенда |
| `src/services/lots.ts` | Загрузка каталога участков |
| `src/data/company.ts` | Реквизиты продавца (футер, страница оплаты, `/#/requisites`) |

Папка `public/` копируется в `dist/` как есть, поэтому PHP-файлы уезжают на
хостинг вместе с сайтом обычным деплоем.

## Каталог участков (Google Sheets)

Цены и статусы ведутся в Google-таблице — менеджер правит её, сайт подхватывает
изменения **без деплоя**. Таблица уже подключена:

```
https://docs.google.com/spreadsheets/d/1i4kgKY5PxjZxSn_tLl7MkIHJdT_9xkOU9eYqIGVCLpk
```

Ссылка на CSV-экспорт прописана значением по умолчанию в `.github/scripts/make-config.py`.
Переопределить можно переменной `LOTS_SOURCE_URL`.

**Важно: таблица должна оставаться доступной по ссылке** («Доступ по ссылке — читатель»).
Если доступ закрыть, сайт перестанет видеть участки.

### Колонки

| Колонка | Обязательна | Понимаемые названия |
|---|---|---|
| Посёлок | да | `Посёлок`, `Поселок`, `Район`, `Объект` |
| Участок | да | `Участок`, `№ участка`, `Номер участка`, `Номер` |
| Цена | да | `Цена`, `Стоимость` |
| Площадь | нет | `Площадь`, `Размер` |
| Статус | нет | `Статус`, `Состояние` |
| ID посёлка | нет | `ID посёлка` |
| ID участка | нет | `ID участка` |

- **Цена** — понимает `390150`, `149 000`, `1 450 000 ₽`, `1.450.000`, `1450000,00`.
  Строка без числовой цены в каталог **не попадает** (сейчас так выпадают 4 проданных
  и забронированных участка «Щекинских берегов» — это нормально).
- **Статус** → `Свободен`, `Акция`, `В продаже`, пусто = можно оформить;
  `Продан` = продан; **всё остальное считается занятым**. Так безопаснее:
  лучше не продать, чем продать один участок дважды.
- **Площадь** показывается ровно так, как записана в ячейке. Единицу
  автоматически не дописываем — см. предупреждение ниже.

### Площадь: единицу нужно писать в таблице

Сейчас площадь ведётся голым числом, и единицы **смешаны**:

| Посёлок | Как записано | Что означает |
|---|---|---|
| Щекинские берега | `8,67`, `7,91` | сотки |
| Светлая | `100`, `130`, `150` | сотки |
| Светлая, участки **2, 8, 15** | `1,2`, `1,3`, `1,6` | **гектары** |

Что участки 2, 8 и 15 записаны в гектарах, видно по цене: №2 за 178 800 ₽ стоит
столько же, сколько №5 с площадью `120`. То есть `1,2` здесь = 120 соток.

Поэтому код **не дописывает единицу сам** — иначе для этих трёх участков он написал бы
«1,2 сот.» вместо 1,2 га, ошибка в сто раз. Правильное решение — привести таблицу
к одному виду и писать единицу прямо в ячейке: `8,67 сот.`, `1,2 га`.

### Кэш

Таблица скачивается не чаще раза в 5 минут, результат лежит в `public/api/cache/lots.json`.
Если Google недоступен — сайт работает на последнем удачном кэше; если и кэша нет —
на `lots.json`. Цены при этом не теряются и участки не становятся бесплатными.

### Защита

Заявку можно подать **только на участок из каталога**: произвольную сумму сервер
не принимает, цену берёт по `id` участка. Участок со статусом не `free` оформить
нельзя — сервер вернёт ошибку, даже если подделать запрос.

## Что нужно сделать, чтобы оплата заработала

### 1. Договор с ЮKassa

Нужны юрлицо/ИП и подключённый магазин. В личном кабинете ЮKassa:
**Настройки → Магазин** — там `shopId` и секретный ключ.

### 2. Онлайн-касса (54-ФЗ)

Приём оплаты от физлиц требует кассового чека. Варианты:
- подключить кассу через ЮKassa (тогда чек формирует она — код уже это делает);
- использовать свою кассу и отключить чеки на стороне ЮKassa.

Пока касса не подключена, поставьте переменную `YOOKASSA_SEND_RECEIPT=false`,
иначе ЮKassa отклонит платёж из-за отсутствия данных чека.

### 3. Секреты в GitHub

Репозиторий → **Settings → Secrets and variables → Actions**.

Вкладка **Secrets** (значения скрыты):

| Имя | Значение |
|---|---|
| `YOOKASSA_SECRET_KEY` | секретный ключ ЮKassa (**единственное, что обязательно добавить**) |
| `TELEGRAM_BOT_TOKEN` | токен бота для уведомлений об оплатах |
| `GAS_WEBAPP_URL` | URL Google Apps Script (та же таблица, что и заявки) |

Вкладка **Variables** — необязательные, есть значения по умолчанию:

| Имя | По умолчанию | Смысл |
|---|---|---|
| `YOOKASSA_PAYMENT_METHOD` | `sber_loan` | Способ оплаты. Пусто — показать все методы магазина |
| `INSTALLMENT_MIN_AMOUNT` | `3000` | Минимальная сумма заявки, ₽ |
| `INSTALLMENT_MAX_AMOUNT` | `1500000` | Максимальная сумма заявки, ₽ |
| `RECEIPT_MODE` | `full_payment` | Способ расчёта в чеке. Сверьте с бухгалтером |
| `RECEIPT_SUBJECT` | `commodity` | Признак предмета расчёта в чеке |
| `YOOKASSA_SEND_RECEIPT` | `true` | Формировать чек через ЮKassa |
| `YOOKASSA_VAT_CODE` | `1` | Ставка НДС (1 = без НДС) |
| `YOOKASSA_TAX_SYSTEM_CODE` | не передаётся | Система налогообложения, если их несколько |
| `TELEGRAM_CHAT_ID` | `@gektar_request` | Куда слать уведомления |
| `LOTS_SOURCE_URL` | не задан | Ссылка на Google-таблицу с участками (CSV). Пусто — читаем `lots.json` |
| `YOOKASSA_SHOP_ID` | `1454166` | ShopID магазина client.gektar.expert. Менять, только если завели другой магазин |
| `PAYMENT_RETURN_URL` | `https://client.gektar.expert/#/pay/result` | Куда вернуть клиента |

> Про способ расчёта в чеке: банк перечисляет продавцу всю сумму сразу, поэтому для
> продавца это **полный расчёт** (`full_payment`) за товар (`commodity`).
> Значения вынесены в переменные `RECEIPT_MODE` и `RECEIPT_SUBJECT` — сверьте их
> с бухгалтером, за реквизиты чека отвечает продавец.

> Про НДС: реализация земельных участков НДС не облагается (пп. 6 п. 2 ст. 146 НК РФ),
> поэтому по умолчанию стоит «без НДС». Подтвердите с бухгалтерией — за неверный
> реквизит чека штрафует налоговая, а не мы.

### 4. Вебхук в ЮKassa

Личный кабинет → **Настройки → Уведомления → HTTP-уведомления**:

```
https://client.gektar.expert/api/webhook.php
```

События: `payment.succeeded` и `payment.canceled`.

Без вебхука оплата пройдёт, но менеджер не получит уведомление в Telegram.

### 5. Проверка

После деплоя откройте:

```
https://client.gektar.expert/api/ping.php
```

Ожидаемый ответ — `"curl": true`, `"config_present": true`, `"shop_id_set": true`.
Если вместо JSON скачивается файл или видно исходный код — на хостинге не включён PHP,
надо включить его в панели reg.ru для домена.

Затем проведите тестовый платёж на минимальную сумму и верните его из личного
кабинета ЮKassa.

## Тексты сайта, которые больше не соответствуют схеме

Рассрочку теперь оформляет **банк**, а не собственник. Эти места нужно переписать —
я их не трогал, потому что это заявления о финансовом продукте, а не вёрстка:

- **FAQ**, вопрос «Как оформляется рассрочка?» — сейчас там «оформляется напрямую
  с собственником, **без банка**» и «первый взнос от 30%».
- **Блок «Почему мы»** — «Рассрочка 0%. Без банка и процентов».
- **Калькулятор** — считает по схеме 30% + 12 месяцев от собственника. Условия
  банковской рассрочки задаёт банк при оформлении, они могут отличаться.
- **Раздел «Как купить»** — шаг про первый взнос от 30%.

Если старая схема (рассрочка от собственника) сохраняется наряду с банковской —
тексты можно оставить, но стоит развести два варианта явно, иначе клиент запутается.

## Локальная разработка

PHP на dev-сервере Vite не работает — запросы к `/api/*.php` вернут HTML вместо JSON,
и форма покажет ошибку «сервис не вернул ссылку». Это ожидаемо.

Чтобы отладить фронтенд против боевого API, создайте `.env.local`:

```
VITE_API_BASE=https://client.gektar.expert
```

Origin `http://localhost:5175` уже прописан в `allowed_origins` конфига.

Dev-сервер: `npm run dev` → http://localhost:5175
(порт 5175, а не 5174 — 5174 занят старой версией сайта в папке «сайт для клиентов»).
